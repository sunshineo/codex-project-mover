# V1 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release `codex-project-mover` as `v1.0.0` with the current Mac-first CLI contract, documented install paths, a tagged source state, an Apple Silicon macOS binary, and a Homebrew tap formula.

**Architecture:** Keep the release manual and auditable for v1. The release flow verifies the current `main`, documents Homebrew/source/binary installation, bumps crate metadata to `1.0.0`, commits, tags, builds release artifacts from the tag, generates SHA-256 checksums, pushes branch and tag, creates a GitHub release, and publishes a Homebrew formula that builds from the release source archive.

**Tech Stack:** Rust/Cargo, Git, GitHub remote `origin`, optional GitHub CLI `gh`, Homebrew, macOS `shasum`.

- [ ] **Step 3: Write the formula from the release source checksum**

Run:

```bash
source_sha="$(cut -d ' ' -f1 dist/codex-project-mover-1.0.0.tar.gz.sha256)"
formula_path="$(brew --repository sunshineo/tap)/Formula/codex-project-mover.rb"
mkdir -p "$(dirname "$formula_path")"
cat > "$formula_path" <<EOF
class CodexProjectMover < Formula
  desc "Move a Codex Desktop project folder and update local Codex metadata"
  homepage "https://github.com/sunshineo/codex-project-mover"
  url "https://github.com/sunshineo/codex-project-mover/releases/download/v1.0.0/codex-project-mover-1.0.0.tar.gz"
  sha256 "$source_sha"
  license "Apache-2.0"

  depends_on "rust" => :build

  def install
    system "cargo", "install", *std_cargo_args
  end

  test do
    assert_match "codex-project-mover 1.0.0", shell_output("#{bin}/codex-project-mover --version")
    assert_match "plan", shell_output("#{bin}/codex-project-mover --help")
  end
end
EOF
```

- `Formula/codex-project-mover.rb` exists in the tap checkout.

## Task 11: Abort And Cleanup Paths

**Files:**
- Local and remote Git state
- Optional GitHub release state
- Optional Homebrew tap state

- [ ] **Step 1: Abort before pushing**

If the release fails before `git push origin main` or `git push origin v1.0.0`, run:

```bash
git tag -d v1.0.0
git reset --hard HEAD~1
```

Expected:
- Local tag is removed.
- Local release version commit is removed.

- [ ] **Step 2: Abort after pushing tag or release**

If the tag or release has already been pushed and nobody has consumed it, run:

```bash
gh release delete v1.0.0 --yes
git push origin :refs/tags/v1.0.0
git tag -d v1.0.0
git revert <release-commit>
git push origin main
```

Expected:
- GitHub release is deleted if it existed.
- Remote tag is deleted.
- Local tag is deleted.
- Release version commit is reverted instead of rewriting pushed `main`.

- [ ] **Step 3: Abort after public consumption**

If users may already have downloaded the artifact or referenced the tag, do not delete or recreate `v1.0.0`. Prepare a fixed follow-up release such as `v1.0.1`.

Expected:
- Public release history remains monotonic after consumption.

- [ ] **Step 4: Abort after Homebrew tap failure**

If the GitHub release is valid but the Homebrew formula fails, keep `v1.0.0` intact and fix the tap formula in a follow-up tap commit.

Expected:
- The GitHub release is not deleted solely because the tap formula needs a correction.
- The tap history records the fix as a new commit.
