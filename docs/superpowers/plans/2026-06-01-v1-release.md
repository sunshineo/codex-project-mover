# V1 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release `codex-project-mover` as `v1.0.0` with the current Mac-first CLI contract, documented install paths, a tagged source state, and an Apple Silicon macOS binary plus checksum.

**Architecture:** Keep the release manual and auditable for v1. The release flow verifies the current `main`, documents source-build and direct-binary installation, bumps crate metadata to `1.0.0`, commits, tags, builds a release artifact from the tag, generates a SHA-256 checksum, pushes branch and tag, and creates a GitHub release. Homebrew remains a post-v1 follow-up because a formula can point at the immutable `v1.0.0` tag after release.

**Tech Stack:** Rust/Cargo, Git, GitHub remote `origin`, optional GitHub CLI `gh`, macOS `shasum`.


## Task 10: Abort And Cleanup Paths

**Files:**
- Local and remote Git state
- Optional GitHub release state

- [ ] **Step 1: Abort before pushing**

If the release fails before `git push origin main` or `git push origin v1.0.0`, run:

```bash
git tag -d v1.0.0
git reset --hard HEAD~1
```

Expected:
- Local tag is removed.
- Local release version commit is removed.

- [ ] **Step 2: Abort after pushing tag or release**

If the tag or release has already been pushed and nobody has consumed it, run:

```bash
gh release delete v1.0.0 --yes
git push origin :refs/tags/v1.0.0
git tag -d v1.0.0
git revert <release-commit>
git push origin main
```

Expected:
- GitHub release is deleted if it existed.
- Remote tag is deleted.
- Local tag is deleted.
- Release version commit is reverted instead of rewriting pushed `main`.

- [ ] **Step 3: Abort after public consumption**

If users may already have downloaded the artifact or referenced the tag, do not delete or recreate `v1.0.0`. Prepare a fixed follow-up release such as `v1.0.1`.

Expected:
- Public release history remains monotonic after consumption.
